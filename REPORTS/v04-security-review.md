# TERRANEX v0.4 보안 점검 및 작업 상태

## 확인된 문제
- 현재 로그인은 사용자명 조회와 로컬 계정 전환 방식입니다. Supabase Auth 세션이 없으므로 `auth.uid()`를 이용한 소유권 확인이 불가능합니다.
- 기존 `supabase/schema.sql`의 쓰기 RLS 정책은 `WITH CHECK (true)` / `USING (true)`를 사용합니다. 공개 서비스에 적용하면 사용자 위조 및 임의 상태 변경 위험이 있습니다.
- 기존 `test_v04.js`는 별도 구현한 모의 DB를 시험합니다. 실제 브라우저 앱이나 Supabase 권한을 검증하지 않습니다.

## 이번 수정
- `supabase/migrations/20261122_lockdown_unauthenticated_writes.sql`: 기존 취약 쓰기 정책을 제거하고 클라이언트 쓰기 권한을 차단하는 선택적 마이그레이션을 추가했습니다.
- 이 SQL은 자동 실행되지 않았습니다. 운영 DB에 적용하기 전에 백업 및 별도 테스트 환경 검증이 필요합니다.
- **중요:** 이 마이그레이션을 적용하면 클라우드 모드에서 가입·프로젝트 생성·도전 신청 등 모든 쓰기가 차단됩니다. 이는 인증 기능이 없는 현재 상태에서 의도한 안전 조치입니다.
- 로컬 에뮬레이션 모드는 신뢰할 수 없는 데모입니다. 다른 사용자의 데이터에 대한 실제 접근 통제를 제공하지 않습니다.

## 다음 필수 개발
1. Supabase Auth 도입: 사용자별 로그인 및 `profiles.id = auth.uid()` 관계 정립
2. 사용자별 RLS 정책: 프로젝트 소유자, 도전자, 방어자 역할 검증
3. 서버측 상태 전이 검증: PROPOSED → ACCEPTED/REJECTED → EVIDENCE_SUBMITTED → OFFICIALLY_RECORDED
4. 증거 및 장부 중복 방지: 고유 제약 및 트랜잭션/RPC
5. 실제 Supabase 환경에서 사용자 A/B 권한 우회 테스트
6. 테스트 결과를 실제로 실행한 범위만 보고하도록 CI와 자동화 러너 개선
